Write a git commit message for my current changes. I will commit manually.

## Current repo state
- Status: !`git status --short`
- Diff summary (staged): !`git diff --staged --stat`
- Diff summary (unstaged): !`git diff --stat`
- Recent commits: !`git log --oneline -n 10`

Extra instructions from me (may be empty): $ARGUMENTS

## Steps
1. If nothing is staged, say the changes are unstaged and use them anyway.
   If there are no changes at all, or this is not a git repo, say so and stop.
2. Read the actual diff with `git diff --staged` (or `git diff` if nothing
   is staged). For a very large diff, inspect the most important files only.
3. Use the diff for WHAT changed and our conversation for WHY. If they
   disagree, the diff wins; mention the mismatch briefly.

## Style
- Match the convention in the recent commits. If there is none, use
  Conventional Commits: `type(scope): subject`
  (feat, fix, refactor, perf, style, docs, test, build, ci, chore, revert).
- Scope: the feature or area touched (e.g. dashboard, auth, users). Omit it
  if the change spans many areas.
- Subject: imperative mood, 72 characters or fewer, no trailing period,
  describes the outcome ("fix crash when list is empty").
- Body (only if the subject is not enough): blank line, wrap at about 72
  characters, explain WHY and notable trade-offs, short bullets for several
  changes. Do not restate the diff line by line.
- Footer only when relevant: `BREAKING CHANGE: ...`, `Refs: #123`.
- English, unless the recent commits use another language.

## Mixed changes
If the diff holds unrelated changes (e.g. a fix, a refactor, and a dependency
bump), propose a split instead of one message: list each commit with its
message and the files it covers.

## Output
- The message in one code block, ready to copy and paste.
- One line listing the files it covers (or the proposed split).
- If I wrote "short", give a one-line subject only.

## Rules
- Only read-only git commands (status, diff, log). Never run `git commit`,
  `git add`, `git push`, or anything that changes the repo or its history.
- Do not output a `git commit` command unless I ask for one.
- Describe only what is in the diff. Do not claim tests pass or bugs are
  fixed unless the diff or our conversation shows it.
- No co-author, "generated by", or other attribution trailers.
- If the diff contains secrets (API keys, tokens, .env contents, private
  keys), warn me first and never quote them in the message.
